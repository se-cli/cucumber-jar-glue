它解决什么问题

现状

  • Cucumber step definition 经常被打包进测试支撑 JAR，源码不在工作区。
  • VSCode 侧只能索引 workspace 里的 .java，Gherkin 步骤因此显示“未定义”。
  • 手工解压依赖既慢又不可维护，IDEA Cucumber 插件也不解决 VSCode 的索引缺口。

本扩展

  • 从依赖 classpath 中找出 JAR，在内存中读 ZIP 中央目录与条目。
  • 解析 .class 常量池和 RuntimeVisible/InvisibleAnnotations，提取 Glue 元数据。
  • 与工作区 .java 源码索引合并，统一提供 Gherkin 语言功能。

核心能力

定义跳转

Gherkin 步骤直接跳到 JAR 内 Glue 方法，或工作区源码。JAR 定义打开只读声明视图，展示注解、类名、方法签名与参数个数。

查找引用

从 Glue 定义反查所有使用它的 Gherkin 步骤；也能从步骤定位到定义，再列出全部引用位置。

步骤补全

输入步骤时提示 JAR 与源码中的 pattern，标注来自哪个 JAR 的哪个类方法，源码定义优先排序。

诊断提示

未找到匹配时给出 Warning，多个等价定义时给出 Information；索引不完整会明确标注结果可能不全。

增量更新

监听 pom.xml / build.gradle* / .classpath 变化，重算 classpath 后只扫描新增或身份变化的 JAR。

参数类型

识别 ParameterType 的 name 与 regexp，让自定义 Cucumber Expression 参数类型参与匹配。

编辑器兼容：同时绑定 gherkin 与 cucumber language id，并以 **/*.feature 兜底。Cucumber 官方扩展把 .feature 注册为 cucumber，两种语言 ID 下跳转、引用、补全和诊断都可用。

顺序来源说明
1Java 语言服务器java.project.getAll 取项目 URI，再对所有匹配项目调 java.project.getClasspaths 并合并，优先 test scope；兼容多模块
2Mavenmvn dependency:build-classpath：按模块分别输出 classpath 再合并，子模块 pom 变化会触发刷新

错误提示与性能控制

状态栏显示定义数与 JAR 数；输出通道记录每个 JAR 的耗时、跳过原因和损坏条目。扫描跑在 worker_threads 中，单 JAR 超时终止并替换 worker；危险正则（嵌套量词）直接拒绝；JAR 大小、条目数、解压大小均有上限。任何单个 JAR 失败都不会阻止扩展激活。

边界与限制

跳转 JAR 内定义打开的是声明视图，不是反编译源码。它由 .class 元数据生成，包含注解、类名、方法签名与参数个数，用于导航和引用查找；方法体不可见。
匹配不是 Cucumber 运行时的完整实现。覆盖常用 Cucumber Expression 子集（参数类型、可选文本、alternation）和 Java 正则；运行时自定义 transformer 的语义不解析。

其他已知边界：仅支持 Java 项目中的 Glue 索引；Java 语言服务器未就绪或项目尚未导入时，classpath 请求可能得不到响应；Gradle 回退依赖临时 init script，复杂多项目构建需要实际验证。
